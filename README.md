# واحة الرياضيات — مشروع المحرّك (مصدر التطبيق)

هذا المجلد هو **مصدر** تطبيق «واحة الرياضيات» (الهندسة للأطفال). التطبيق الذي يُعطى للأطفال يبقى **ملفاً واحداً** يعمل دون اتصال
(`dist/واحة_الرياضيات.html`)، لكنه لم يعد يُكتب يدوياً: خطوة بناء صغيرة تجمعه من الأجزاء أدناه (قرار الميثاق D246).

## ماذا في كل مجلد؟

| المجلد | ما فيه | من يلمسه؟ |
|---|---|---|
| `content/` | **المحتوى التعليمي كبيانات** (ملفات JSON مقروءة): النصوص المنطوقة، سجلّ الأخطاء، الوحدات، الدروس | مالك المنهج / الاختصاصي — بلا خوف من كسر الكود |
| `content/strings/gen.json` | الجمل العامة لكل الدروس: المدح، تفسير «حل مشترك»، جمل التحدي والمراجعة والورشة والمعرض والاستراحة (`gen.*`) | |
| `content/strings/labels.json` | أسماء السلال (دائرة، مربع، مكعب…) | |
| `content/errors.json` | **سجلّ الأخطاء الواحد**: لكل وسم خطأ اسمٌ يراه الكبار في اللوحة (`label`) وتفسيرٌ يسمعه الطفل (`explain`) | |
| `content/m1/u1/unit.json` | الوحدة الأولى: العنوان، المضيفون، أشكال صيد الكاميرا، ألغاز الورشة | |
| `content/m1/u1/d1.json` … `d5.json` | كل درس: العنوان والأيقونة، التمرين (السلال، الأشكال المولَّدة، الأخطاء، أسباب الصواب)، مشهد «صحّح لفوضى»، جمل الختام ومهمة البيت، بطاقة الحوار، وأسئلة التحدي في درس المراجعة | |
| `content/m1/u2/…` | الوحدة الثانية بالطريقة نفسها | |
| `src/` | **كود المحرّك**: `head.html` و`styles.css` و`body.html` وJS في `src/js/` مقسّمة بحسب المسؤولية (الصوت، الرسم، الأدوات، الدروس، المشغّل، الورشة، لوحة الكبار…) | المهندس |
| `build/` | خطوة البناء: `build.mjs` (الدمج)، `lint.mjs` (فحوص المحتوى)، `script.mjs` + `script_xlsx.py` (جدول التسجيل الصوتي)، `clips.mjs` (جمع الجمل) | المهندس |
| `assets/fonts/` | مكان ملف الخط `BalooBhaijaan2.woff2` إن أردنا تضمينه | |
| `test/` | أدوات الفحص الآلي (Playwright) ومقارنة البنى | المهندس |
| `dist/` | **الناتج**: الملف الواحد للأطفال، ونسخة الفحص، وجدول التسجيل | يُولَّد آلياً؛ لا يُحرَّر |
| `docs/MIGRATION.md` | ما بقي كوداً في الدروس وخطة تحويله إلى بيانات | |

## كيف أبني الملف؟

يلزم Node (الإصدار 18 فأعلى) فقط. من داخل مجلد المشروع:

```
node build/build.mjs
```

يُنتج `dist/واحة_الرياضيات.html` (نسخة الأطفال) ويطبع:

1. **نتيجة فحص المحتوى**: عدد الجمل والأخطاء والدروس، وأي مخالفة توقف البناء (جملة بلا نص، صيغة مخاطبة ناقصة، معرّف مكرّر، وسم خطأ بلا تفسير…).
2. حالة **الخط**: مضمّن أو لا.
3. **جدول التسجيل** `dist/script_m1.xlsx` (يلزم له Python مع openpyxl؛ وإن لم يتوفّر يُكتب `dist/script_m1.json` فقط).

نسخة الفحص (تُبقي خطافات الفحص الآلي ووضع `#fast` الذي يقصّر الانتظار):

```
node build/build.mjs --dev
```

تُنتج `dist/واحة_الرياضيات.dev.html`. **لا تُعطى هذه النسخة للأطفال.**

لتشغيل فحوص المحتوى وحدها دون بناء: `node build/lint.mjs`.

## كيف أشغّل الفحوص؟

تلزم Python 3 مع `playwright` (ومتصفح Chromium مثبّت له) و`openpyxl`.

| الأمر | ماذا يفحص |
|---|---|
| `node build/lint.mjs` | المحتوى (انظر أعلاه) |
| `python3 test/smoke_prod.py` | نسخة الأطفال تفتح، ويبدأ الدرس الأول، ولا خطافات فحص فيها، ولا أخطاء |
| `python3 test/check_script_ids.py` | معرّفات جدول التسجيل مطابقة لما كان يستخرجه السكربت القديم من الملف المرجعي |
| `python3 test/compare_structs.py A.html B.html` | البنى البيانية لملفين متطابقة (يفيد بعد أي تغيير في طريقة الربط) |
| `sh test/run_all.sh dist/واحة_الرياضيات.dev.html test/out/dev` | كل مسارات التجربة الآلية (الدروس التسعة ولداً وبنتاً، إخفاق الإتقان، الجلسة والاستراحة، الورشة والمعرض، القارئ الآلي) على نسخة الفحص؛ النتائج في `test/out/dev/*.txt` |
| `SEED=7 sh test/run_all.sh <ملف> <مجلد>` ثم `python3 test/compare_runs.py <مجلد A> <مجلد B>` | المسارات نفسها بعشوائية مثبّتة على ملفين (مثلاً المرجع القديم والبناء الجديد) وجدول مقارنة للنتائج المطبوعة |

## كيف أعدّل جملة أو أضيف درساً؟

**تعديل جملة:** افتح ملف JSON المناسب (الدرس أو `gen.json` أو `errors.json`)، وعدّل النص فقط، وأبقِ المعرّف (مثل `"hook.01"`) كما هو لأن ملفات الصوت تُسمّى به.
صيغتا المخاطبة تُكتبان بين قوسين مع شرطة: `{اِلْمَسْ|اِلْمَسِي}` (الولد أولاً ثم البنت)، واسم الطفل `{name}`. ثم `node build/build.mjs` — وإن أخطأت في الصيغة أوقفك الفحص وأخبرك بالمكان.

**إضافة درس كبيانات (ما يمكن اليوم):** انسخ درساً شبيهاً، مثل `content/m1/u1/d2.json` إلى `d6.json` وعدّل فيه:

- `id` (مثل `m1.u1.d6`) و`title` و`icon`؛
- `sort`: السلال `bins`، وجملة البداية `intro`، والأشكال بالاسم في `practice` (التمرين) و`sets` (مجموعتا الإتقان، ثلاثة أشكال في كل مجموعة) و`remedial` (المسار العلاجي). الأسماء المتاحة هي مولّدات الأشكال في `src/js/35_makers.js` (`circle`, `plate`, `squareRot`…) و`52_lessons_u2.js` (`cube`, `drum`…)، ويمكن تمرير وسيط: `["squareRot", 45]`؛
- `sort.errors`: وسوم الأخطاء التي يستعملها الدرس (كل وسم يجب أن يكون في `errors.json` مع تفسير)، و`sort.reasons`: أسباب الصواب بمعرّفاتها؛
- `chaos`: الأشياء الموضوعة في السلال (واحد منها `"wrong": true`)، والسببان (واحد `"ok": true`)؛
- `wrapLines` و`homeTask` و`talk`.

ثم يبقى الجزء الإجرائي: في `src/js/50_lessons_u1.js` أضف كتلة `LESSONS.push(lesson('m1.u1.d6', W => ({ hook, explore, worked, sort: { errorOf, showErr, reason, twin, recall }, wrap })))` على نسق الدروس الحالية (انظر `docs/MIGRATION.md` لما سيصير بيانات في الخطوة التالية). البناء يرفض الدرس إن أشار إلى مولّد غير موجود أو وسم خطأ بلا تفسير.

**إضافة خطأ جديد:** أضف إلى `errors.json` مدخلاً `"tagName": { "label": "ما يراه الكبار", "explain": { "gen.err.tagName.01": "ما يسمعه الطفل" } }` ثم استعمل الوسم في `sort.errors` للدرس وفي `errorOf`.

## كيف أضيف ملف الخط؟

1. نزّل خط **Baloo Bhaijaan 2** (رخصة OFL) بصيغة `woff2` (يفضَّل مجموعة جزئية عربية + أرقام لتصغير الحجم).
2. ضعه باسم `assets/fonts/BalooBhaijaan2.woff2`.
3. `node build/build.mjs` — سيطبع «الخط: مضمّن»، ويُحذف رابط Google من الملف، فيعمل الخط دون اتصال.

إن لم يوجد الملف، يبقى الرابط غير الحاجب كما هو مع بدائل خطوط النظام العربية.

## ملاحظات

- **لا تحرّر `dist/` يدوياً**؛ أي تعديل يُكتب في `content/` أو `src/` ثم يُعاد البناء.
- المحتوى بالعربية الكاملة التشكيل كما في جدول التسجيل؛ المعرّف ثابت والنص قابل للتغيير.
- `dist/script_m1.xlsx.ids.json` هو قائمة أسماء ملفات الصوت المطلوبة (`m1.u1.d1.hook.01.mp3`، و`_m`/`_f` للجمل ذات الصيغتين).
